# 2026.242.1606 — feat(WP4): advance pod-cstream to the build carrying the resize gate

## Summary

Advance `pod-cstream` to `v2026.242.1603`, the build that pins the streamer revision carrying the
**runtime control socket** and authors **WP4's resize gate** against it.

**What the gate proves.** Each resize is paired with a `wl: hypr-monitors` observation, because the
socket reply proves only that the *streamer* applied new caps and says nothing about whether the
compositor reconfigured its output. Aquamarine snaps an unsatisfiable configure to 1280×720 **in
silence**, so neither "no error" nor "the streamer said OK" is evidence.

Measured on the bed that tag was gated by:

```
resize 1600 900  ->  socket: OK resize 1600x896  ->  monitor: "width": 1600  "height": 896
resize 640 480   ->  socket: OK resize 640x480   ->  monitor: "width": 640   "height": 480
```

A capsfilter rewrite propagates through gst-wayland-display to Hyprland's monitor, and the
compositor reports **896** — the rounded height, which is the value that can only appear if
round-to-8 reached the far end of the chain.

## A correction this carries forward

The plan's WP4 gate lists `1600×900` as a size to assert. **900 is not a multiple of 8**, so
`Geometry::sanitised()` applies it as `896` — a gate asserting the requested value would fail
against correct behaviour. The gate in the pinned tag asserts `1600x896` with the reason inline.

`3840×2160` is **not** gated: this bed runs rootless on a shared iGPU, a 4K reconfigure is a
materially different resource claim, and it has not been measured. It belongs with
`check-cstream-vm` (WP9b). Named rather than dropped.
