# 2026.242.0422 — feat: the cstream desktop metalayer

## Summary

The cstream desktop metalayer: `pod-cstream` (the transport spine — parent, gateway, PAM stack and
the streaming gates) composed with `pod-hyprland` (the nested compositor), as one name.

**Composition order is the reason this is a candy rather than two lines in every consumer.**
Hyprland has no headless mode — 0.56.2 exposes no `--headless` flag and no
`HYPRLAND_HEADLESS_ONLY`, verified against the shipped binary — and Aquamarine's DRM backend
requires a KMS card node a rootless pod never gets. It therefore only runs *nested*, inside a
parent that advertises `zwp_linux_dmabuf_v1` and binds `xdg_wm_base` at **exactly 6**.
`pod-cstream` supplies that parent. Composing `pod-hyprland` on its own produces an image that
**builds cleanly** and dies at start with `CBackend::create() failed!` — an error that names the
compositor rather than the missing parent, which is precisely the mistake this layer exists to
make unmakeable.

It installs nothing of its own. That is deliberate: a metalayer that also installed things would
give a consumer two places to look for the same behaviour, and both members already own theirs.

**4. A defect this caught before it shipped — the members were first authored under `require:`.**
The image build refused it outright:

```
charly: error: command "build": validation error: candy "cstream-desktop":
  must have at least one install file (candy manifest distro: packages, root.yml,
  pixi.toml, pyproject.toml, environment.yml, package.json, Cargo.toml, or user.yml),
  a candy: field, an external_builder:, or a plugin: block
```

`require:` declares a dependency; `candy:` declares membership, and a metalayer's members are what
it *is*. The schema was saying the same thing, and the fix is `candy:` — the field
`pod-selkies-desktop` uses for exactly this shape. The reason is recorded in the file so the next
author does not repeat it.
