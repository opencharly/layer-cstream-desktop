# 2026.242.1712 — feat(WP5): advance both members to the builds carrying the wl: tooling

## Summary

Advance both members to the builds carrying the `wl:` verb's wlroots tooling:

```
pod-cstream    v2026.242.1603 -> v2026.242.1710
pod-hyprland   v2026.242.0634 -> v2026.242.1704
```

`pod-hyprland v2026.242.1704` ships `wl-clipboard`, `wtype` and `wlr-randr` beside `grim` — the
binaries `wl:` shells out to for clipboard, type/key-combo and resolution. Without them those verbs
fail on `command not found` rather than on anything about the desktop, which is why none had ever
been exercised against this compositor.

## Why both pins move in one change

This metalayer composes both members, and **`pod-cstream` also pins `pod-hyprland` independently**.
So advancing either alone leaves two versions of `pod-hyprland` in the graph — measured on this
branch before the ordering was fixed:

```
Warning: candy github.com/opencharly/pod-hyprland resolved to multiple versions;
         using newest 2026.242.1640 (from …@v2026.242.1704),
         ignoring 2026.242.0620 (from …@v2026.242.0634)
```

Those two numbering spaces are the candy's declared `version:` field and, in parentheses, the git
tag it was fetched from — not the same number, and not a contradiction:

```
pod-hyprland @ v2026.242.0634  ->  candy version: 2026.242.0620
pod-hyprland @ v2026.242.1704  ->  candy version: 2026.242.1640
```

`opencharly/pod-cstream#10` moved the inner pin first, so this advance lands at **zero warnings**
rather than relying on `PickCandyVersion`'s newest-wins tie-break to cover a stale declaration.

## A behaviour these tags make reachable — routed to `opencharly/pod-cstream#11`

Shipping `wlr-randr` makes `wl: resolution` functional on a cstream desktop, and measured there it
is harmful: it moves the compositor while the streamer's capsfilter stays put, desyncing encoder
from compositor with no error anywhere. That is filed as **`opencharly/pod-cstream#11`** with the
measurement, a reproduction and three costed options.

The `check-cstream-pod` bed deliberately does **not** gate that verb and says so inline. The binary
still ships because `wl:` serves other compositors where the verb is correct.
