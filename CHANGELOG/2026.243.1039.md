# 2026.243.1039 — chore: advance pod-hyprland so the chain reaches one plugin-wl version

## Summary
    require:  @github.com/opencharly/pod-hyprland   ->  v2026.243.1021

pod-hyprland#9 advanced its plugin-wl pin to v2026.243.1001, which carries the fix for two
verbs that BLOCKED on commands that do not exit: wl exec (a GUI app that never returns) and
wl clipboard set (wl-copy staying alive to own the selection). Both reported failure for
operations that had succeeded.

Until this pin moves, that fix reaches nobody through this path - and worse, this path keeps
the OLD plugin-wl in a closure that also contains the new one, so charly resolves the candy at
two versions and warns. Measured on the omarchy desktop bed after it moved to v2026.243.1001:

    4 non-allowlisted warnings across one R10 run

This is the second of four ordered repins. The pattern is now familiar enough to state
plainly: a version split closes only when EVERY path to the candy arrives. Advancing one
consumer ahead of its chain does not fix a split, it opens one.
