# 2026.242.1137 — feat: advance pod-cstream to the WP3c tag

## Summary

Advance `pod-cstream` from `v2026.242.0658` to `v2026.242.1124`, which carries **WP3c**: the
streamer is now the Wayland parent rather than a process running beside one.

`waylanddisplaysrc` creates a compositor **and holds the render node**, so a second one cannot
observe the first's display. The old arrangement therefore had the streamer capturing its **own
empty compositor** while the desktop drew into a separate parent — which is why signalling
negotiated a WebRTC session end-to-end and no media ever followed. The new tag replaces the
separate parent: one pipeline captures, taps and encodes, and Hyprland nests into the streamer's
own display.

## Change classification

**Change class:** candy/box-config — one pinned tag, one candy `version:`. No Go, no schema, no
workflow, single repo.

**Verification gate:** `check-cstream-desktop`, a `disposable: true` bed composing **this metalayer
and nothing else**, with no repo overrides.

**Breaking change + rollback:** none in shape. The behavioural consequence is that the composed
desktop's streamer owns the display it streams. Rollback returns to a split parent/streamer where
nothing can consume the stream.

**Producer → consumer order:** satisfied — `pod-cstream v2026.242.1124` is merged and published,
and pins `charly-streamer` at the merged `#7`.

## Scope note

The `cstream:` verb checks are deliberately **not** in this bed. They need `plugin-cstream` in
charly's scan range for the `primary:` scalar shorthand to resolve, and this metalayer composes the
*desktop* — the transport spine and the compositor — not the check plugin. Those checks live in the
pod bed, which does compose it. Adding the plugin here to satisfy a check would put a test
dependency into a shipped desktop layer.
